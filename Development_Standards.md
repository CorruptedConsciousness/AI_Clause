# Development Standards

## Purpose

This document outlines the development principles and quality expectations applied to projects maintained by this repository's owner.

These standards apply to independently written and AI-assisted software alike.

## 1. Code Quality

- Prioritize readable, understandable, and maintainable code.
- Use descriptive variable and function names.
- Organize programs into logical components.
- Minimize unnecessary complexity and duplication.
- Refactor existing code as knowledge and experience improve.

## 2. Testing and Verification

- Test software functionality before publishing when practical.
- Verify that implemented features behave as intended.
- Investigate errors, unexpected behavior, and known limitations.
- Never assume AI-generated code is correct simply because it executes.

Testing procedures and coverage will vary according to project complexity and available resources.

## 3. AI-Assisted Development

- AI may assist with code generation, debugging, architecture, documentation, and research.
- Review and test AI-generated contributions as practical.
- Maintain transparency regarding substantial AI involvement.
- Retain human responsibility for development decisions and published work.
- Use AI assistance to support continued technical education and independent problem-solving.

See [AI Assistance & Development Disclosure](AI_Disclosure.md).

## 4. Documentation

Projects should include documentation appropriate to their complexity, including:

- Project purpose and intended functionality.
- Installation and configuration instructions where applicable.
- Hardware and software dependencies.

## 5. Version Control

- Use Git for tracking development changes.
- Maintain meaningful commit histories.
- Document significant changes when appropriate.
- Avoid publishing credentials, API keys, or sensitive information.
- Use public repositories when appropriate for the project.

## 6. Security and Reliability

- Consider security implications when developing and publishing software.
- Avoid embedding sensitive credentials directly in source code.
- Validate external inputs when applicable.
- Do not represent experimental software as production-ready without appropriate verification.

## 7. Continuous Improvement

Software development is an ongoing learning process.

Projects may undergo substantial revisions as programming knowledge, technical requirements, and available tools evolve.

Earlier implementations are retained or documented when useful for demonstrating development history and technical progression.

---

**These standards represent development goals and practices, not a guarantee that every published project satisfies every criterion.**
